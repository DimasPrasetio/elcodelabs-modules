## Known limits

What is known and accepted for now — read before relying on the area. Remove a line when it is
fixed; add one when you accept a limit.

- **Audit is best-effort (kernel).** When writing an audit record fails, the kernel logs it and
  the change still commits, so a reopened period or a raised number can lack its security
  record. Candidate for a kernel request.
- **Testbed flake under load (kernel).** `TestMySQLDedupeQueuesBehindARunningTask` can time out
  when the machine is busy (other MySQL work running). It passes alone; rerun before blaming a
  module.
- **Stale page data on a company switch.** `useResource` (ui-core) keeps the previous company's
  data visible for the length of one reload. The server checks every write again.
- **Lock queue and deadlocks (`period`).** While a lock date change waits, new postings queue
  behind it; a module that calls `EnsureOpen` after taking other row locks can deadlock, which
  `d.Tx` retries. The recipe calls it first.
- **Numbers are unique per document type (`numbering`).** Two types written to one consumer table
  with the same pattern are not checked against each other: one type per table.
- **Rupiah only (`money`).** No currency code on amounts (decision K4); the first module that
  needs foreign currency adds it.
- **No hard lock (`period`).** A closed period can be reopened by `period.unlock` (decision K6).
- **Customers and suppliers per company (`customers`, `suppliers`).** A group of companies
  keeps a customer once per company (decision K1); a party that is both customer and supplier is
  two records with no link yet.
- **NPWP check digit is unofficial (`taxid`).** DJP has not published it: a mismatch only warns.
  Whether a number is registered, or a party is a PKP, is not checked (Coretax only).
- **Addresses are free text (`customers`, `suppliers`).** No Kemendagri region codes yet
  (decision K8).
